# かぎ針編み図アプリ 実装計画

このドキュメントは、実装をどの順番で進めるかと、各フェーズの完了条件を定義する。編み物のルールは domain-spec.md、画面と操作は ui-spec.md、技術方針は tech-spec.md を参照する。

---

## 0. 進め方

- フェーズは番号順に進める。フェーズの完了は「そのフェーズのチケットがすべて完了し、main にマージされ、フェーズの完了条件を満たしている」こと。
- 1つのタスクは Jira の1チケットに対応させる（運用は CLAUDE.md）。フェーズ0〜3 のタスクはチケットの大きさで書いてある。フェーズ4以降は粒度が粗いので、**各フェーズに着手するとき、最初にタスクをチケットの大きさに分け直す**。
- 仕様の判断が必要になったら、勝手に決めずに止めて質問する。仕様書の更新が必要な場合は、そのチケットの中で行う。
- フェーズの最初に「決めておくこと」がある場合は、それを決めるチケットを先に片付ける。

### MVP の範囲

フェーズ0〜5 を MVP とする。**輪編み・わの作り目の作品を1色で作り、記号図と目数表を A4 の PDF・画像に書き出せる**状態。

MVP に含めないもの（フェーズ6以降）：螺旋編み、往復編み、鎖の作り目、束に編み入れる（モチーフ）、色（糸リスト・色編集モード・色替え位置の表示）、サムネイル、作品カードのメニュー。

## フェーズ0：土台

**目的**：コマンドラインでビルドとテストが回る状態にし、CrochetCore パッケージの置き場所を確定する。

**決めておくこと**：なし（AMIZ-1 で決定済み。tech-spec 1・2・4-1）

### タスク

**0-1 プロジェクト設定**
- 最低 OS を 26.0 にする（3ターゲットとも）
- 開発言語を ja にする
- `.gitignore` を追加し、`xcuserdata` の追跡を解除する
- 共有スキーム `Amiz` を作り、テストの対象を AmizTests のみにする（AmizUITests は外す。ターゲットは残す）
- 完了条件：シミュレーター向けの `xcodebuild build` が通る。`git ls-files` に `xcuserdata` が含まれない。`xcodebuild -list` に共有スキーム `Amiz` が出る

**0-2 CrochetCore の骨組み**
- リポジトリ直下に `CrochetCore/` を作る（`Package.swift`、Swift 6 言語モード、platforms は iOS 26 と macOS 26、Swift Testing のテストターゲット）
- 中身は仮の型1つとテスト1つでよい
- アプリターゲットにローカルパッケージとして紐付け、アプリ側で `import CrochetCore` してビルドが通ることを確認する
- CLAUDE.md の「コマンド」欄に、アプリのビルド・アプリのテスト・CrochetCore のテストのコマンドを記入する
- 完了条件：`swift test`（CrochetCore 内）が通る。アプリのビルドとテストが通る。CLAUDE.md の3つのコマンドがそのまま実行できる

### フェーズの完了条件

## フェーズ1：エンジン（輪編み）

**目的**：輪編み・わの作り目について、目数・警告・修正の影響範囲を正しく計算できる。画面はまだ作らない。

**決めておくこと**：なし

**対象外**：螺旋編み・往復編み・鎖の作り目・束に編み入れる・色。ただしデータモデルの型（編み方の種類、作り目の種類、操作の種類）には最初から含めておく。

### タスク

**1-1 データモデル**
- 目の種類、操作（立ち上がり／普通の目／n目編み入れる／n目一度／鎖編み／飛ばす／残りは編まない／段を閉じる引き抜き／束に編み入れる）、繰り返し（単位＋回数、または段の終わりまで）、段、作り目（わ／鎖 n目）、編み方、作品全体（`schemaVersion` 付き）
- 段・操作・繰り返しに ID を持たせる。繰り返しの中の目の指し方（段ID, 操作ID, 何回目）を決める（tech-spec 5-3）
- `Codable`・`Sendable` の値型（tech-spec 5-2）
- 完了条件：TC-1 の作品をコードで組み立て、JSON に変換して戻すと元と等しいテストが通る

**1-2 手順の展開と目数**
- 段の展開：繰り返しの展開、「段の終わりまで」「残りすべてに」の回数決定（余りは残す。domain-spec 17）
- 段ごとの「拾った目数」「合計目数」「鎖を除いた目数」（domain-spec 8・21）
- 完了条件：TC-1・TC-3・TC-4 の目数、TC-6 の繰り返し回数（6回、1目残る）がテストで通る

**1-3 整合性チェック**
- 段ごとの警告（不足・過多）、警告文、「残りは編まない」の扱い、わの作り目の1段目の除外（domain-spec 23）
- 完了条件：TC-2「上の段を残す」後の各段の警告有無と文言、TC-6 の警告がテストで通る

**1-4 修正の影響範囲**
- 段の置き換え・削除・複製に対する影響範囲（「3〜5段目」）の計算
- 「上の段を残す」（そのまま拾い直す）と「上の段をほどく」（上の段を削除）の適用（domain-spec 25）
- 完了条件：TC-2 の両方の選択肢と TC-5 がテストで通る

**1-5 目数表の文章**
- 手順の文章化（「（細編み1目、細編み2目編み入れる）×6」「細編み2目編み入れる×全目」「立ち上がり鎖3目」など）、目数の表記（「合計36目／鎖抜き12目」）
- 同じ内容の段が続く場合のまとめ（「5〜9段目：細編み30目（増減なし）」。domain-spec 18）
- 完了条件：TC-1〜TC-4 の手順文が ui-spec 8章のサンプルと一致するテストが通る

### フェーズの完了条件
- TC-1〜TC-6 が `swift test` で通る（TC-7 はフェーズ7）

## フェーズ2：仮の編集画面

**目的**：シミュレーターで輪編みをキーボードから入力し、目数表で結果を見られるようにする。図はまだ無い。見た目は最低限でよく、フェーズ4で作り直す前提。ただし編集の状態管理（2-1）はフェーズ4でもそのまま使う。

**決めておくこと**：なし

**対象外**：図、目の選択、過去の段の編集、保存（アプリを閉じると消えてよい）、作品一覧（起動すると直接編集画面が開く）

### タスク

**2-1 編集の状態管理**
- 今の作品、入力中の段、先に選ぶボタンの選択状態、操作の追加と1目削除
- 元に戻す／やり直し（編み図全体のスナップショット。tech-spec 9）
- エンジンの呼び出し（展開・目数・警告）
- 完了条件：アプリ側の単体テスト（AmizTests）で「ボタン操作に相当する呼び出し→目数」「元に戻す→やり直し」が通る

**2-2 編み目キーボード**
- 目ボタン6つ、先に選ぶボタン（2目編み入れる／2目一度／飛ばす／残りすべてに。「束に」は表示だけで無効）、同時選択の組み合わせ
- 段の操作（繰り返し開始／終了と回数入力、段を終える、1目削除、立ち上がり）
- 立ち上がりの自動挿入（ui-spec 5-6 U5。設定は仮の切り替えでよい）
- 完了条件：シミュレーターで「くまの頭」の1〜3段目を入力できる

**2-3 現在の段と目数表**
- 進み具合（拾った目／前段の目数、わの作り目の1段目は分母なし）、直前3目の表示
- 目数表（作り目の行、段番号、手順、目数、警告、まとめ表示）
- 完了条件：TC-1 の5段を入力すると、目数表が TC-1 の期待値と一致する

**2-4 段を終えるときの確認と拾いすぎ**
- 7-2 のダイアログ（残りは編まない／このまま終える／戻って続ける）
- 前段を使い切ったときの「前段を使い切りました」表示（ui-spec 5-5）
- 完了条件：前段に目を残して終えると警告が出る、「残りは編まない」を選ぶと出ない、拾いすぎて終えると警告が出る、をシミュレーターで確認できる

### フェーズの完了条件
- シミュレーター（iPhone 17）で「くまの頭」の5段をキーボードで入力し、目数表が TC-1 と一致する
- 元に戻す／やり直しが動く

## フェーズ3：円形図の試作

**目的**：tech-spec 8-1 の方針で実物の編み図に近い円形図が描けるかを確かめる。ここが技術的に一番不確かなので、本番の画面より先に試す。

**決めておくこと**：なし（3-4 で判断する）

### タスク

**3-1 レイアウト計算（CrochetCore の Layout 層）**
- 段の半径（段の高さの累計）、目の角度（編み入れ先の角度を基準に、n目編み入れは均等に広げ、n目一度は中間、鎖は前後の間に等間隔）、立ち上がりと段を閉じる引き抜きの位置、段内で記号が重ならない調整、記号の向き（domain-spec 12）
- 完了条件：TC-1 の作品の各目に位置・角度・高さ・向きが計算される。同じ段の目の角度が編む順に単調に増える。増し目の2目が同じ根元を持つ。これらがテストで通る

**3-2 記号の描画**
- Path で描く記号：6種の目、立ち上がり（鎖の連なり）、段を閉じる引き抜き、n目編み入れる（根元を1点に集める）、n目一度（頭を1点に集める）、繰り返し範囲の括弧（domain-spec 10・11・19）
- 完了条件：すべての記号を並べたプレビューがあり、JIS の記号として読める

**3-3 図のビュー**
- Canvas で図全体を描く。ピンチでズーム、ドラッグで移動。段番号の表示。今編んでいる段の区別。次に拾う前段の目のハイライト（ui-spec 5-3）
- タップした位置に一番近い目を判定する（選択の操作自体はフェーズ4）
- 完了条件：仮の編集画面に図を追加し、入力に合わせてハイライトが進む

**3-4 見た目の評価と方針の判断**
- 「くまの頭」（細編み・増し目）と「花のモチーフ」の2段目（長編み・鎖）を描き、実物の編み図と比べる
- 数千目のダミーデータでズーム・移動の滑らかさを確かめる
- 8-1 の方針をそのまま続けるか調整するかを決め、tech-spec 8-1・13 を更新する
- 完了条件：開発者が図の見た目を承認し、tech-spec 13 の「円形図の見た目」「描画の性能」が解決済みになっている

### フェーズの完了条件
- 3-1 のレイアウトのテストが通る
- シミュレーターで「くまの頭」と「花のモチーフ」の円形図が表示され、開発者が見た目を承認している
